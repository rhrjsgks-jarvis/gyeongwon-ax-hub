# 구독 정보 수집 → 고정 자료 → 빌드 → 검사 → 실물 확인

삼성닷컴 구독 지면이 바뀌면 이 순서로 돈다. **손으로 회차표를 옮겨 적지 않는다** — 삼성 표를
칸 단위로 받아 빌드가 해석한다. 사람이 옮기는 것은 「케어 종류 → 항목」 정의 하나뿐이다.

## 0. 로컬 세션인지 확인
수집은 브라우저로 삼성닷컴을 렌더해야 해서 **로컬 전용**이다(클라우드 세션은 프록시가 막는다).

## 1. 품목별 구독케어 수집
```
npm run collect:care                      # 15개 품목 전부 (2026-10-16 시스템에어컨·제습기 추가)
npm run collect:care -- fridge,kimchi     # 일부만
```
- `scripts/collect-care-subs.mjs` → `scripts/fixtures/care-subs.json`(품목별 원문: 정의 문단 · 탭별 사진 · 회차표 칸 · 유의사항)
- **못 받은 품목은 옛 값을 둔다**(표·탭·정의 중 하나라도 비면 쓰지 않는다). 출력에 `✗` 가 뜨면 그 지면 구조가 바뀐 것이다.
- 지면 주소(`T`)가 404·빈 화면이면 카테고리 목록 `…/?only-ai-subs` 를 열고 `goodsList` 응답의 `goodsDetailUrl` 로 고친다.
- 탭 사진에서 **원문 HTML 주석으로 빠진 사진은 `hidden`** 이다 — 그 유형에 없는 항목이라 화면에 안 띄운다(에어컨 라이트의 「실외기 냉매 점검」「스마트 진단」이 그 예).

## 2. 케어 정의 확인 (사람이 하는 유일한 단계)
`scripts/fixtures/care-kinds.mjs` — 품목별 「케어 종류 → 항목」. 원문은 `care-subs.json` 의 `products.<품목>.block`.
- 표에 **정의 없는 케어 이름**이 나오면 다음 단계 빌드가 멈춘다 → 원문 정의 문단을 그대로 옮겨 넣는다.
- 라이트가 같은 이름의 케어를 받는데 항목이 다르면 원문이 그렇게 적을 때만 따로 적는다.
- 셀프케어 배송 소모품은 `deliver` 에 이름을 넣는다.

## 3. 빌드
```
npm run build:careplans
```
- `public/care-app.html` 의 `CARE-PLANS:BEGIN/END` 사이를 갈아 끼운다(손으로 고치지 말 것).
- 출력으로 품목별 요금제(P12·P36·P6·L12·L36·S6·S12)·횟수·사진 수가 찍힌다 — 지난번과 견줘 이상한 것이 없는지 본다.

## 4. 블루패스 (전 품목 공통)
가이드 `https://www.samsung.com/sec/ai-subs/guide/` 의 「새로워진 블루패스」·「스페셜 패스」·「블루패스 유의 사항」을 읽고
`public/care-app.html` 의 `const BLUEPASS` 를 고친다. 조건(target·need·except·cost)은 **유의사항 원문 문장에서만**.
타일 사진은 `images.samsung.com/kdp/static/uiux/subhub_guide/season2/…` → `public/care-img/` 로 받는다(배경 이미지라 렌더해서 찾는다).

## 5. 검사
```
npm run test:care          # 빌드 신선도(--check) + 화면·골든 회차·접기/펴기·블루패스 조건·공유
```
- 골든(`scripts/test-care.mjs` 3-b)은 **원문 표에서 눈으로 확인한 값**이다. 원문이 바뀌었으면 원문을 보고 고친다 — 앱 출력을 그대로 베끼지 말 것.
- 블루패스 `MUST` 문구도 같다.

## 6. 실물 확인 (반드시)
`public/` 을 웹 서버로 띄우고(`file://` 로는 공유 내려받기를 못 잰다) 폰 폭(430px)으로:
- 품목마다 유형 탭 · O/X 표 · 설명 멘트 · 계약기간별 표 · 사진 수가 원문과 맞는가
- 「모두 펼치기/접기」, 유형을 바꿔도 열어 둔 섹션이 유지되는가
- **`npm run audit:careclip`** — 폭 320~430 × 품목·유형·주기 전부에서 잘린 글자·칩이 없는가(「잘림 0건」이어야 한다)
- **공유 버튼을 실제로 눌러** 저장된 이미지가 화면 전체 높이를 담는가(접힌 섹션은 접힌 채로 나간다 — 의도된 동작)

## 7. 마무리
- `sw.js` 의 `CACHE_VERSION` 과 앱 버전을 올린다(care-app.html 은 SWR 대상).
- 앱 머리말 날짜(「YYYY.MM.DD 기준」)와 출처 문구를 수집 날짜로 고친다.
- 커밋은 묻고, push 는 CLAUDE.md 배포 규칙대로.

## 하지 말 것
- 비슷한 품목의 회차·사진을 빌려 채우지 않는다(원문에 없으면 없다고 적는다).
- 원문끼리 어긋나면(예: 신혼 패스 「쉬운 시작 안내」 5개월차 ↔ 4개월차) 한쪽을 고르지 않고 둘 다 밝힌다.
- 가격은 담지 않는다.
