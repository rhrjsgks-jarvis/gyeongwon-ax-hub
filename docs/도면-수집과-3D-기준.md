# 도면 수집과 3D 렌더링 기준

> 수기로 도면을 모을 때 **어떤 도면이 3D 로 잘 서는지**, 앱에서 **무엇을 확인해야
> 하는지**를 적는다. 수치는 전부 2026-08-18~19 에 실제로 재서 얻은 것이다.

---

## 1. 어떤 도면이 3D 로 잘 서는가

### ★ 가장 중요 — **벽이 검게 칠해진 도면**

AI Hub 「건축 도면 데이터」의 정답(벽 폴리곤) 90장으로 채점한 결과다:

| 도면 유형 | 벽 검출 재현율 | 정밀도 |
|---|---|---|
| **벽이 칠해짐** | **90.8%** | 53.3% |
| 반쯤 칠해짐 | 50.3% | 71.3% |
| 윤곽선만(속이 빈 벽) | 17.4% | 68.6% |

**분양 마케팅 도면은 대개 칠해져 있다** — 그래서 우리 주력 입력이 가장 잘 된다.
CAD 시공 도면(윤곽선)은 절반 이하로 떨어진다. **같은 단지라면 분양 도면을 고를 것.**

### 그다음 — **치수가 인쇄돼 있는가**

축척이 있어야 가전을 올릴 수 있다. 치수가 인쇄돼 있으면 **자동으로 읽힌다**.

| | 치수 인쇄 비율 |
|---|---|
| 우리가 모은 분양 도면 697장 | **8%** |
| LH 「주택 평면도 현황」 | **100%** (자동 판독 6/6 성공) |
| GH 임대주택 공고 | 없음 (전용면적만) |

치수가 없어도 쓸 수 있다 — 화면이 **"안방 가로가 몇 mm 입니까"** 를 묻는다.
고객이 아는 치수를 넣으면 된다(보통 3,000~3,600mm).

### 피해야 할 것

- **한 장에 세대가 여럿인 시트** — 우리 인식은 "한 도면 = 한 세대"를 전제한다
- **입체(아이소메트릭)·인테리어 사진·품목표** — 목록에서 자동으로 걸러지지만(기울기 0.35 미만)
  섞여 들어오면 글씨가 벽이 된다
- **도면 둘레에 흰 여백이 넓은 것** — 여백이 방으로 잡혀 넓이가 부풀고 이름이 밀린다
  (LH 하남 46B 에서 여백 11.5㎡ 가 「현관」으로 잡혔다)

## 2. 앱에서 하는 일 — 순서와 확인 지점

```
① 도면 열기            단지 목록에서 고르거나 파일로 올린다
② 축척 확정            자동으로 고른 주황색 벽의 길이(mm)를 넣는다
③ 벽 자동 인식         집 전체를 한 번에 잡는다
④ 확인하고 고친다      ← 여기가 사람 몫이다
⑤ 방 이름 붙이기
⑥ 내보내기            JSON 하나 → 개발자에게 전달 → npm run merge:library
```

### ④에서 반드시 볼 것 셋

**(a) 넓이가 전용면적과 비슷한가**
잡힌 방 넓이의 합이 전용면적의 **0.9~1.4배**면 정상이다(발코니·실외기실이 더해져 조금
넘는 것이 보통). 1.6배를 넘으면 **여백이나 옆 세대가 섞인 것**이다.

**(b) 가장 넓은 방이 거실인가**
아니면 방이 잘못 합쳐진 것이다. `◂ 더 좁게 / 더 넓게 ▸` 로 닫기 단계를 옮긴다.

**(c) 도면 바깥이 방으로 잡히지 않았는가**
겹쳐 보기(◧)로 확인한다. 잡혔으면 그 방을 지운다.

> **트인 거실+주방이 한 덩어리로 잡히는 것은 정상이다** — 일부러 그렇게 두고 목록에
> `30.1㎡ · 주방 포함` 이라고 적는다. 억지로 쪼개지 말 것.

## 3. 3D 가 지금 무엇을 그리고 무엇을 못 그리는가

### 그린다
- **벽** — 두께는 도면에서 재고 100~300mm 로 자른다. 못 재면 200mm
  (예전 60mm 가정은 정답 23,861개 중앙값의 3분의 1이라 종이 판처럼 보였다)
- **바닥** — 원본 도면 이미지를 그대로 텍스처로 입힌다. 마루색·가구가 살아난다
- **개구부** — 문·창 자리는 벽을 세우지 않고 위에 인방(2,100mm)만 남긴다
- **가전** — 실측 W×H×D 상자 + 최소 디테일(도어선·화구·그릴). **24개 카테고리 전부**
- **도어 열기** — 열리는 도중까지 훑어 부딪히면 빨갛게 칠한다

### 못 그린다 (근거가 없어서)
| | 왜 |
|---|---|
| **문인지 창인지 구분** | 정답 20만 건으로 5겹 교차검증했으나 **기준선 80.5% 를 못 넘었다**(81.2%). 작은 욕실 창과 방문이 같은 폭이다. 그래서 화면이 `문·창` 으로 함께 적는다 |
| 힌지 방향(좌/우) | 도면·카탈로그 어디에도 없다. 문짝이 하나인 제품은 손으로 뒤집는다 |
| 층고 | 평면도에 없다. **2,300mm 가정**이고 화면이 그 사실을 밝힌다 |
| 창턱 높이 | 문·창을 못 가리니 창대를 그리면 문을 창으로 단정하게 된다 |

> 참고 — 문은 **97%가 여닫이**(궤적 있음), 창은 **71%가 미닫이**(궤적 없음)다
> (AI Hub `attributes` 전수). 못 가릴 때 어느 쪽으로 기울여야 하는지의 근거다.

### 개구부 검출은 아직 약하다
정답으로 재니 **도달률 29.3% · 판별률 38.9%** 다(문 13.5% · 창 44.2%).
다만 이 수치는 **한 장에 세대가 여럿인 CAD 시트** 기준이라 그대로 매장 성능으로 읽으면
안 된다 — 같은 잣대로 우리 분양 도면을 재면 **덩어리 현상이 0장**이다(40장 실측).

## 4. 모은 것을 공용 목록에 넣는 법

```
npm run merge:library <내보낸파일.json> --dry    먼저 미리보기
npm run merge:library <내보낸파일.json>          실제로 합치기
```

**관문 5종이 자동으로 검사한다** — 이미지·base64 섞임(저작권) · 벽 3개 미만 ·
한 변 30m 초과 · 방 1~200㎡ 밖 · 타입 숫자 대비 넓이 0.6~1.6배 · 단지/타입 이름 없음 · 중복.

**이미지는 절대 담지 않는다.** 나가는 것은 **벽선(방 경계 mm 좌표)** 뿐이다 —
분양 도면은 저작권이 있어 저장소에 둘 수 없지만 파생 측정값인 좌표는 담을 수 있다.
그래서 **부동산 포털을 보고 손으로 벽선을 잡는 것**도 이 원칙 안에서 가능하다
(robots.txt 는 자동 수집 규칙이라 사람이 보는 것은 대상이 아니다).
