# AI Hub 도면으로 배치 시뮬레이터 3D 재설계 — 작업 지시문

> 로컬 세션은 세션마다 `CLAUDE.md` 를 읽고, 거기서 이 파일을 가리킨다.
> 기간 1주 · 토큰 여유 있음. **먼저 `CLAUDE.md` 의 「가전 배치 시뮬레이터」 절 전체와
> 「벽 검출을 정답으로 채점했다」 이하 세 절을 읽을 것.**

---

## 1. 이번 작업이 지금까지와 다른 점

지금까지 AI Hub 데이터는 **채점표**였다 — 픽셀로 추정한 벽이 정답과 얼마나 맞는지 재는 자.
그 결과가 `pairedFill` 같은 실제 개선으로 이어졌다(전체 재현율 24.4 → 45.1%).

**이번에는 자가 아니라 재료로 쓴다.** 라벨의 벽·창·문 폴리곤을 **그대로 지오메트리로 임포트**해
3D 공간을 세운다. 추정 단계가 통째로 빠지므로 벽 위치 오차가 원리상 0 이 된다.

목적은 하나다 — **가전을 사기 전에 우리 집에 놓아 보는 것.**
그래서 **벽 위치와 치수가 맞는 것**이 전부고, 렌더링 품질은 그 다음이다.

## 2. 데이터 — 경로와 이미 알아낸 것

```
239.건축 도면 데이터/        ← 저장소 루트 바로 아래. 약 25.4GB
```

- 로컬 세션의 작업 디렉터리가 곧 저장소 루트이므로 **이 상대경로를 그대로 쓴다.**
- 폴더 이름에 **한글·점(.)·공백**이 섞여 있다. 셸에서 **반드시 따옴표로 감쌀 것** —
  `"239.건축 도면 데이터"`. MSYS 는 따옴표 없이 경로를 쪼갠다.
- `.gitignore` 에 이미 등재돼 있다(main). **확인만 하고 넘어간다** — 이 저장소는 public 이라
  `git add -A` 한 번이면 25GB 가 그대로 공개된다.

**이미 확인된 사실 — 다시 조사하지 말 것** (출처: `CLAUDE.md` 2026-08-18 절)

| 항목 | 실측 |
|---|---|
| 형식 | **COCO** (categories / images / annotations, 폴리곤 segmentation) |
| 검증셋 `APT_FP_STR` | **830장** · 장당 주석 136개 |
| 라벨 종류 | 구조_벽체 · 구조_창호 · 구조_출입문 (여닫이/미닫이/기타 구분) · **공간(SPA)** |
| 표본 300장 라벨 수 | 벽체 23,861 · 창호 8,435 · 출입문 8,120 |
| 이미지 크기 | **4963 × 3509 균일** |
| 한 시트에 평면 여럿 | **49%** (표본 200장) |
| 도면이 시트에서 차지하는 넓이 | 중앙값 **25.5%** (최소 1.3%) |
| 성격 | 분양 유니트 평면도가 아니라 **CAD 시공 도면 시트** — 치수선·표제란·KEY-MAP·층 평면도 섞임 |

기존 하네스도 있다 — `.scratch/aihub-wall-eval.mjs`(벽) · `.scratch/aihub-room-eval.mjs`(공간).
**둘 다 앱의 `useImage` → `ensureClean` 경로를 그대로 타고 내부를 흉내 내지 않는다.**
새로 만들지 말고 읽고 재사용할 것.

## 3. 0단계 — 축척. **여기가 최대 관문이고, 안 풀리면 계획이 바뀐다**

**이 작업의 전제가 아직 확인되지 않았다.** `CLAUDE.md` 는 이렇게 적고 있다:

> **축척 재보정은 못 한다 — 개요 CSV(`scale`)가 정식개방데이터에 없다.**
> 지면 규격에는 "건축 개요 및 도면정보 .csv 1개"가 적혀 있지만 **zip 20개 어디에도 없다(전수 확인).**

라벨 좌표는 **픽셀**이다. 픽셀만으로는 mm 를 알 수 없고, **mm 를 모르면 가전을 올릴 수 없다**
(이 도구의 규칙: 축척 없이는 가전을 아예 올리지 않는다).

**순서대로 두드려 보고, 되는 지점에서 멈춘다:**

1. **설명서·구축활용가이드 다운로드** — 개요 CSV 가 거기 있을 수 있다(AI Hub 로그인 필요).
   있으면 `scale` 열이 무엇을 뜻하는지(1:100? mm/px?) 확인하고 **한 장으로 검산**한다.
2. **라벨에 치수 텍스트가 있는가** — COCO `categories` 를 전수로 찍어 볼 것.
   치수선·치수문자 카테고리가 있으면 그것으로 축척이 나온다.
3. **도면 이미지의 치수 사슬 OCR** — 이미 만들어 둔 `scale-lib.mjs`(사슬 눈금 → mm/px,
   PSM 12, 쌍마다 따로 내고 중앙값)가 있다. 4963×3509 고해상도라 우리 코퍼스보다 유리하다.
   **확신도 '확실'·'보통'만 채택**하는 기존 규칙을 그대로 지킬 것.
4. **위 셋이 다 안 되면** — 임포트는 여전히 가치가 있다(벽 **모양**이 정답이다).
   그때는 **기존 축척 확정 흐름**(벽 하나 길이 입력)을 그대로 태운다.
   화면이 *"모양은 도면 데이터, 치수는 입력값"* 이라고 밝히면 된다.

> **여기서 반드시 보고하고 멈춘다.** 1·2·3 중 무엇이 됐는지에 따라 아래가 달라진다.
> **어떤 경우에도 축척을 지어내지 말 것** — 틀린 축척은 어림값보다 나쁘다(90장으로 확인된 결론).

## 4. 1단계 — 시트에서 세대를 잘라낸다

**한 시트에 평면이 여럿인 것이 49%** 이고, 층 평면도(계단실·엘리베이터)도 섞여 있다.
우리 방 인식은 *"한 도면 = 한 세대"* 를 전제하므로 **이걸 안 풀면 그 아래가 전부 어긋난다.**
(방 인식 절대 점수가 IoU≥0.5 에서 22% 로 낮게 나온 원인도 여기에 있다.)

- 벽 폴리곤의 **연결 성분**으로 덩어리를 나누고, 덩어리마다 경계상자를 낸다.
- **공간(SPA) 라벨이 세대를 가려 준다** — 거실·침실·주방이 한 덩어리 안에 함께 있으면 세대,
  계단실·EV 홀만 있으면 공용부다. 이름 목록을 전수로 찍어 보고 규칙을 세울 것.
- 잘라낸 덩어리마다 **면적 합**을 내서 세대로 말이 되는 범위(대략 30~200㎡)를 벗어나면 버린다.
  축척이 없으면 이 검사는 못 한다 — 0단계 결과에 따른다.
- **버린 것은 사유별로 집계**한다. 조용히 넘기지 않는다.

산출물: 시트 → 세대 N개로 쪼갠 결과표 + 표본 10장의 절단 결과 PNG(눈으로 확인).

## 5. 2단계 — 임포터 (먼저 샘플 20~30장만)

라벨 → 우리 모델로 옮긴다:

| 라벨 | 우리 모델 |
|---|---|
| 구조_벽체 폴리곤 | `state.rooms[].parts[].walls` (닫힌 직교 다각형) |
| 구조_창호 · 구조_출입문 | 벽 위의 **개구부 구간** — 지금 `classifyEdges` 가 만들던 것과 **같은 모양** |
| 공간(SPA) | `state.rooms[].name` (라벨 이름을 우리 표기로. 화면 표기는 `침실1` 우선) |
| 축척 | `state.mmPerPx` + `state.scaled` (0단계 결과에 따라) |

- **폴리곤은 벽 두께 전체를 덮는다.** 우리 벽 모델은 **안목 경계**(방 안쪽 면)다.
  두 개는 다른 것이므로 **벽 폴리곤에서 방 쪽 면을 뽑아야 한다.** 여기서 두께 절반을
  잘못 잡으면 방이 통째로 넓거나 좁아진다 — **면적으로 검산할 것.**
- **검산**: 임포트한 방 넓이 vs 공간(SPA) 라벨 넓이. **IoU 0.9 미만이면 그 장은 버리고 집계.**
  (지금 픽셀 인식이 IoU≥0.5 에서 22% 다. 임포트는 90% 대가 나와야 의미가 있다 —
  **안 나오면 임포터가 틀린 것**이지 데이터 탓이 아니다.)
- **자동 픽셀 인식을 "대체"하는 것이지 "제거"하는 것이 아니다.** 라벨 없는 도면 697장과
  고객이 그 자리에서 올리는 도면이 그대로 남는다. **축척 확정 흐름은 반드시 살려 둔다.**

## 6. 3단계 — 3D 재설계 (샘플로 먼저, 전량 전에)

- **벽**: 폴리곤이 두께를 주므로 **가정값 60mm 를 버리고 실제 두께로 세운다.**
  층고는 여전히 도면에 없다 — 가정값이라고 화면에 밝힌다(지금 2,300mm 를 밝히는 방식 그대로).
- **창**: 투명 유리 + 프레임(사용자 결정 — *"창문은 투명 상태로 둬도 상관없다"*).
  우리가 필요한 것은 **가전을 배치할 벽이 있는 공간**이다. 아래턱 높이는 라벨에 없으면 가정값 표기.
- **문**: **개방 상태로 그린다**(사용자 결정). 그리고 **개폐 궤적과 가전이 겹치면 경고**한다.
  - 라벨이 **여닫이/미닫이**를 구분한다 — **미닫이는 스윙이 없다.** 종류별로 다르게 그릴 것.
  - 여닫이의 힌지·개폐 방향이 라벨에 있으면 쓰고, **없으면 양쪽으로 추정하고 "추정"이라고 밝힌다.**
  - 판정은 기존 `doorHits` 를 재사용한다 — **12단계 스윕**을 도는 이유가 있다(다 열린 자세만
    보면 90° 부근에서 가장 튀어나오는 구간을 놓친다). 대상만 *가전의 문* → *집의 문* 으로 바꾼다.
  - **이건 하드 경고다.** 배치 단계의 `DOOR_ZONE` 주의(힌지를 몰라 양쪽에 그리는 추정값)와
    성격이 다르다 — 여기는 사용자가 직접 문을 여는 행동이고, 라벨이 근거를 준다.
- **돌하우스 컬링 · 시점 프리셋 · 이름표 토글 · 접지 그림자**는 그대로 살린다.
- **바닥 텍스처는 결정이 필요하다.** 지금은 원본 도면을 바닥에 깔아 "우리 집" 느낌을 낸다.
  AI Hub 이미지를 그렇게 쓸 수 있는지는 **이용약관에 달렸다 — 2단계 보고 때 함께 물을 것.**
  못 쓰면 단색 바닥 + 방 이름표로 간다.

## 7. 4단계 — 가전 3D 자산 결합

- **먼저 재고조사**: 대표모델 3D 가 어디에 · 무슨 포맷 · 몇 개 · **단위(m/mm)** ·
  원점이 어디인가(바닥 중심? 경계상자 중심?). **저장소에는 아직 GLB 가 없다.**
- **`public/size-reps.json` 의 W×H×D 와 대조할 것.** 어긋나면 자산을 믿지 말고 보고한다 —
  치수가 이 도구의 존재 이유다.
- 로딩은 **지연 로드**. three.js 를 `public/vendor/` 에 자체 호스팅한 것과 같은 이유
  (매장 전파가 약해도 열려야 한다). 용량 예산을 먼저 정하고 그 안에서 쓴다.
- **자산이 없는 품목은 기존 상자 + 디테일을 그대로 쓴다.** 섞여도 된다.
- 벽걸이 TV(항상 벽을 등진다 · 창 자리 금지) · 사운드바 정렬 규칙은 그대로 지킨다.

## 8. 5단계 — 전량 임포트 · 경원 지역 매핑

- **지역 정보가 라벨에 있는지 먼저 확인한다.** 없으면 **전량을 쓰되 지역을 지어내지 않는다.**
  관할 30곳(경기 12 시 + 강원 18 시·군) 정의는 `CLAUDE.md` 에 있다.
- 산출물은 **파생 좌표만** — `public/plan-library.json` 확장. 원본 이미지·라벨은 커밋하지 않는다.
- `npm run test:library` 의 불량 4종 검사(이미지 섞임 · 벽 3개 미만 · 비정상 치수 · 이름 없음) 통과.
- 실패는 **사유별로 집계**해 보고한다.

## 9. 6단계 — 검증

- `npm run test:all` (= `npm test` + `test:e2e`) 전부 초록
- `npm run test:plans` · `npm run test:real` — **개선했으면 기준선을 다시 써서 커밋한다**
  (`REAL_BASELINE=write`). 안 하면 개선분이 그대로 굳는다.
- **`.scratch/aihub-room-eval.mjs` 를 임포트 경로에도 돌린다** — 픽셀 인식 22% 대비
  임포트가 몇 %인지가 이 작업의 성적표다.
- **성능 실측**: 매장 폰 기준 첫 로드 · 3D 첫 프레임. 숫자로 보고.
- **실물 왕복 10장**: 임포트 → 3D → 가전 배치 → 문 열기 경고 → 결과 저장까지.

## 11. 규칙 — 어기면 되돌린다

1. **근거 없는 숫자를 화면에 만들지 않는다.** 라벨에 없는 값은 가정값이라고 밝힌다.
2. **기존 회귀 테스트를 지우지 않는다.** 규칙이 바뀌면 테스트도 고치고 **왜 바꿨는지 주석.**
3. **한 번에 여러 개를 고치지 않고, 고쳤으면 넓게 다시 돌려 본다.**
   (티어 규칙을 고치다 티어 역전을 만든 전례가 있다 — 넓게 돌려 보고서야 나왔다.)
4. **push 는 묶어서 한 번.** main push 가 곧 Vercel 배포이고 횟수 한도가 있다.
   미푸시 10커밋이 넘으면 그때 올린다. `sw.js` 의 `CACHE_VERSION` 을 함께 올릴 것.
5. **작업 자물쇠**(`.claude/agent.lock`) — 폰(텔레그램 봇)과 동시에 돌리지 않는다.
6. **막히면 멈추고 보고한다.** 스키마가 다르면, 축척 검산이 어긋나면, 저작권이 불확실하면.

**보고 형식은 매번 같다: 끝난 것 / 남은 것 / 지금 하는 것 / 새로 발견한 할 일.**
