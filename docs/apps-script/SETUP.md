# 팀 전체 사용 데이터 집계 — Google Apps Script 설정 가이드

경원 AX 허브는 지금까지 사용 로그가 **각자 브라우저(localStorage)에만** 저장되고 있었습니다.
임원 시연에서 "실사용 데이터"로 효율성을 보여주려면, 팀 전체 로그를 한 곳(구글시트)에
모으는 웹훅을 켜야 합니다. 아래 순서대로 진행해 주세요. (2~3분이면 끝납니다)

## ⚡ 이미 배포하셨다면 — 건의사항 이메일 알림 추가만 하면 됩니다

전체 새로 설정할 필요 없이 아래 3단계만 하시면 됩니다:

1. 이미 만들어둔 스프레드시트 → **확장 프로그램 → Apps Script** 로 들어가기
2. 열려 있는 코드 전체를 지우고, 이 저장소의 최신 `docs/apps-script/Code.gs` 내용으로 통째로 교체
   (상단에 `FEEDBACK_EMAIL = 'rhrjsgks@gmail.com'` 로 알림 받을 이메일이 이미 설정돼 있습니다.
   다른 주소로 받고 싶으면 이 부분만 원하는 이메일로 바꾸면 됩니다.)
3. **배포 → 배포 관리** → 기존 배포 옆 연필(✏️) 아이콘 → 버전을 **새 버전**으로 선택 → **배포**
   (URL은 그대로 유지되므로 Vercel 환경변수는 다시 건드릴 필요 없습니다)

이렇게 하면 허브 어느 페이지에서든 우측 하단 💬 버튼으로 건의사항을 보낼 때마다
설정한 이메일로 알림이 옵니다.

## 1. 구글 스프레드시트 생성

1. https://sheets.google.com 에서 새 스프레드시트 생성
2. 이름은 원하는 대로 (예: "경원AX허브 사용로그")
3. 시트 탭 이름은 신경 쓰지 않아도 됩니다 — 스크립트가 자동으로 `logs`라는 시트를 만듭니다

## 2. Apps Script 붙여넣기

1. 스프레드시트 메뉴에서 **확장 프로그램 → Apps Script** 클릭
2. 기본으로 열려 있는 `Code.gs` 파일의 내용을 전부 지우고
3. 이 저장소의 `docs/apps-script/Code.gs` 파일 내용을 그대로 복사해서 붙여넣기
4. 상단 저장 아이콘(💾) 클릭해서 저장

## 3. 웹 앱으로 배포

1. 우측 상단 **배포 → 새 배포** 클릭
2. 유형 선택에서 톱니바퀴 아이콘 클릭 → **웹 앱** 선택
3. 설정:
   - **실행 사용자**: 나 (본인 구글 계정)
   - **액세스 권한이 있는 사용자**: **전체** (Anyone) ← 팀원들이 로그인 없이 전송해야 하므로 필수
4. **배포** 클릭 → 처음 배포 시 구글 계정 권한 승인 필요(본인 계정이므로 "고급" → "이동" 눌러서 진행)
5. 배포 완료 후 뜨는 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec` 형태)을 복사

## 4. URL을 저에게 알려주세요

복사한 URL을 저에게 전달해 주시면, 제가 `lib/logEvent.ts`의 `GAS_URL`에 반영하고
관리자 대시보드가 이 시트 데이터를 팀 전체 집계로 보여주도록 연결하겠습니다.

## 참고사항

- **개인정보**: 저장되는 항목은 타임스탬프·모듈명·행동(page_view/search 등)·익명 세션ID·검색어 정도이며,
  이름이나 사번 등 개인 식별 정보는 로그에 포함되지 않습니다(레벨업테스트 응시 정보 등 다른 시트와는 무관).
- **재배포**: 코드를 나중에 수정하면 "배포 → 배포 관리 → 수정 아이콘 → 새 버전"으로 재배포해야
  변경사항이 반영됩니다(URL은 그대로 유지됨).
- **스프레드시트 접근 권한**: 이 시트는 사용자님 구글 계정 소유이므로, 필요 시 팀 관리자에게만
  공유 권한을 주는 방식으로 접근을 제한할 수 있습니다.

# 웹 시험 결과 받기 (`Exam.gs`) — 위와 **다른 배포**다

`tools/레벨업챌린지_시험.html` 이 제출 직후 채점 결과 한 줄을 보낸다.
사용 로그(`Code.gs`)와 **합치지 말 것** — 저쪽은 하루 수천 건이 쌓이는 로그이고
이쪽은 사람이 눈으로 읽고 성적을 매기는 기록이라, 한 시트에 섞으면 묻힌다.
스프레드시트를 따로 두면 권한을 교육 담당에게만 열 수 있다.

## 1. 스프레드시트 + 스크립트

1. 새 Google 스프레드시트를 만든다(시트 이름은 그대로 둬도 된다 — `시험결과` 탭을 스스로 만든다)
2. 확장 프로그램 → Apps Script → `docs/apps-script/Exam.gs` 내용을 그대로 붙여넣는다
3. 배포 → 새 배포 → 유형 **웹 앱** → 실행 **나** / 액세스 권한 **전체** → 배포
   - **'전체'가 아니면 응시자 브라우저가 로그인 지면으로 튕겨 기록이 안 남는다**
4. 발급된 `/exec` 주소를 복사한다

## 2. 시험지에 주소 넣기

`scripts/exam-web-template.html` 의 `var SCRIPT_URL = '';` 에 주소를 넣고
`npm run build:examweb` 을 다시 돌린 뒤 `tools/레벨업챌린지_시험.html` 을 배포한다.

**주소를 넣은 채로 저장소에 커밋하면 검사가 실패한다.** 일부러 그렇게 해 두었다 —
링크로 퍼지는 파일이라, 주소가 박힌 채 나가면 응시 기록이 엉뚱한 시트로 흘러간다.
켜는 것은 **파일을 받는 쪽의 의식적인 선택**이어야 한다.

## 3. 확인

- 시험을 한 판 치고 결과 화면의 **`기록` 칸**을 본다 — `기록됨` 이면 시트에 들어갔다.
- `기록 실패` 가 뜨면 배포 액세스 권한이 '전체'인지부터 본다.
  못 보낸 결과는 그 브라우저에 남아 **다음에 열 때 다시 보낸다**(같은 줄이 두 번 가도
  사번+시험지코드+응시시각으로 걸러진다).

## 참고

- 받는 항목은 **사번 8자리·점수·정답 수·문항 수·시험지 코드·응시 시각·소요 초**뿐이다.
  이름·연락처는 애초에 받지 않는다 — 그 파일은 링크로 퍼질 수 있다.
- `POST` 가 아니라 `GET` 으로 보낸다. 시험지가 `file://` 로 열리는 자립형 HTML 이라
  `POST` 에는 프리플라이트(OPTIONS)가 붙는데 Apps Script 는 그것을 받지 않는다.
- **`Exam.gs` 를 고쳤으면 반드시 다시 배포할 것**(배포 관리 → 새 버전). 저장만으로는 안 바뀐다.

# 팀 게시판 받기 (`Board.gs`) — 위 둘과 **다른 배포**다

로그는 자동으로 쌓이는 수천 건이고, 게시판은 사람이 읽고 쓰는 글이다.
한 시트에 섞으면 글이 로그에 묻힌다 — 스프레드시트를 따로 만든다.

## 1. 스프레드시트 + 스크립트

1. 새 Google 스프레드시트 생성 (이름 예: `세일즈코파일럿 게시판`)
2. 확장 프로그램 → Apps Script → `docs/apps-script/Board.gs` 내용을 그대로 붙여넣기 → 저장
3. 배포 → 새 배포 → 유형 **웹 앱** → 실행: 나 / 액세스 권한: **전체** → 배포
4. 발급된 `/exec` 주소를 복사

## 2. Vercel 환경변수

1. Vercel 프로젝트 설정 → Environment Variables → **`BOARD_GAS_URL`** 에 `/exec` 주소 입력
   - `NEXT_PUBLIC_` 접두를 붙이지 말 것 — 붙이면 화면 소스에 실려 누구나 그 주소로 아무 글이나 밀어 넣을 수 있다
2. **재배포** (환경변수는 기존 배포에 소급되지 않는다 — 대시보드의 Redeploy 버튼이면 된다)

## 3. 확인

- 앱의 `/board` 화면에서 글을 하나 적어 시트 `게시판` 탭에 줄이 붙는지 본다
- 연동 전에는 화면이 "게시판 시트가 아직 연결되지 않았습니다" 를 정직하게 띄운다

## 참고

- 글 삭제·수정은 시트에서 직접 한다 (화면에는 삭제 버튼이 없다 — 로그인 없는 앱이라 "내 글"을 증명할 길이 없다)
- `Board.gs` 를 고쳤으면 **배포 관리 → 새 버전**으로 다시 배포해야 반영된다
