# 벽선 모으기 — 매장이 잡은 벽선을 공용 목록으로

> 상담사용 안내 + 개발자 합치기 절차. 2026-08-18 기준 공용 목록 **6건**.

## 왜 이걸 하나

**도면 이미지 수집은 소진됐다.** 청약홈은 2021-10 이후만 조회되고, 그 전 단지는 분양
사이트가 사라졌다. 건설사 브랜드 지면도 준공 단지 평면도를 남기지 않는다. 관할
3,829개 단지 중 도면이 있는 곳은 **149곳**뿐이다.

그런데 **3D 배치에 정말 필요한 것은 도면 이미지가 아니라 벽 좌표**다. 도면은 벽 좌표를
얻는 수단일 뿐이고, 3D 에 들어가는 순간 이미지는 쓰이지 않는다.

그리고 **벽 좌표에는 저작권 제약이 없다** — 도면의 파생 측정값이기 때문이다. 그래서
`public/plan-library.json` 은 저장소에 담을 수 있고 배포본에 그대로 실린다.

**같은 주택형이면 벽이 같다.** 단지 하나당 주택형 3~5개만 있으면 그 단지 전체가
커버된다. 매장 몇 곳만 참여해도 관할 단지가 빠르게 찬다.

---

## 상담사가 하는 일 — 3단계

고객 도면을 한 번 잡아 두면, 그 단지는 **다음 배포부터 모든 매장이 도면 없이** 쓴다.

1. **방을 잡는다** — 배치 시뮬레이터에서 도면을 올리고 축척을 맞춘 뒤 `벽 자동 인식`.
   화면이 묻는 대로 **안방 가로 길이(mm)** 를 넣으면 도면 전체가 그 비율로 맞춰진다.
2. **`단지 저장`** — 단지명과 주택형을 적는다. 이 기기에 남는다.
3. **`단지 불러오기` → `벽선 보내기`** — 파일 하나가 만들어진다. 그것을 개발자에게 보낸다.
   (카톡·메일 무엇이든 된다. **도면 이미지는 담기지 않는다** — 방 경계 좌표뿐이다.)

`단지 불러오기` 시트가 *"이 기기에 저장해 둔 단지 N곳이 있습니다"* 라고 알려 준다.

### 꼭 지켜 주실 것

- **축척을 맞추지 않은 채로 저장하지 마세요.** 축척이 없으면 좌표가 mm 가 아니라
  그림 픽셀이라, 다른 매장에서 불러오면 **크기가 통째로 틀린 집**이 뜬다.
- **방 이름이 엉뚱한 자리에 붙었으면 고쳐 주세요.** 공용 목록에는 이미지가 없어서,
  받는 쪽에는 이름을 바로잡을 근거가 화면에 없다.
- 잘 모르겠으면 **그냥 보내 주세요.** 아래 관문이 걸러 냅니다.

## 개발자가 하는 일 — 합치기

```bash
npm run merge:library <받은파일.json> --dry   # 먼저 미리보기
npm run merge:library <받은파일.json>          # 담기
npm run test:library                          # 관문이 도는지
git add public/plan-library.json && git commit
```

**커밋해야 매장에 나간다** — 이 파일은 배포본에 그대로 실린다.

### 관문 — 무엇이 걸러지고 왜

쓰레기가 들어가면 그것을 불러온 **다른 매장 상담사가 틀린 치수로 상담한다.** 그래서
합치기 자체보다 거르는 쪽이 이 도구의 값어치다.

| 걸러내는 것 | 왜 |
|---|---|
| 이미지·base64 가 섞임 | 저작권. 공용 목록은 좌표만 담는다 |
| 벽 3개 미만 | 방이 성립하지 않는다 |
| 한 변 30m 초과 · 방 1~200㎡ 밖 | 축척이 틀어진 신호 |
| 단지·주택형 이름 없음 | 목록에서 못 찾는다 |
| 타입 숫자 대비 넓이 0.6~1.6배 밖 | 주택형 이름이 곧 전용면적이라 **바깥 자료 없이 검산된다**. `T1` 처럼 글자가 앞에 붙은 타입은 면적이 아니므로 이 검사를 건너뛴다 |
| 방 3곳 이상인데 가장 넓은 방이 거실이 아님 | 이름이 엉뚱한 자리에 붙은 것 |
| 이미 있는 단지·주택형 | 조용히 덮지 않는다. `--force` 로만 덮는다 |

**범위는 넉넉히 잡았다** — 목적은 "정확한 값 고르기"가 아니라 **"명백히 잘못된 것
거르기"** 다. 좁히면 멀쩡한 것을 막는다.

목록에서 이 단지들은 **`도면 3장 · 저장된 방 3종`** 처럼 표시된다.

**여기서 자동으로 더 늘릴 수는 없다.** 벽선은 mm 좌표라 축척이 있어야 하는데, 색인
696장 중 축척이 확정된 것은 **12장뿐**(치수가 인쇄된 도면이 8%다)이고 그 12장은
이미 다 처리했다 — 6건은 담았고 5건은 위 관문에 걸렸다.
`node .scratch/seed-library.mjs` 를 다시 돌려도 **담기는 것은 0건**이다.

**그래서 이 목록이 자라는 길은 매장이 보내 주는 것뿐이다.**
